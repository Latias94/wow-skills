# 经验沉淀与跨日志归纳

经验不是“某个高手在某一秒按了什么”，而是多个可比日志中重复出现、能解释结果并能被下一把验证的规则。

## 提炼流程

1. 从每场日志抽出相对时间、阶段、目标、关键技能和触发链。
2. 将不同击杀时长按阶段/机制编号对齐，不要只按绝对秒数对齐。
3. 记录至少 3 个可比样本的共同动作、允许偏差和例外。
4. 把共同规律与单场风格分开；单样本只能标记为“待验证”。
5. 用下一场日志验证动作是否改善了窗口伤害、覆盖率、目标价值或生存，而不是只看总 DPS。

## 经验卡格式

```markdown
### <职业/专精> · <首领/副本> · <场景>
- 版本：<正式版本/日期>
- 构筑：<专精/英雄天赋/套装条件>
- 场景：<单体/顺劈/AOE；阶段或小怪波次>
- 触发条件：<何时开始>
- 推荐动作：<中文技能名的先后关系>
- 机制原因：<资源、增益、复制、覆盖、目标寿命>
- 容错边界：<何时延后、改目标或放弃>
- 验证指标：<次数、覆盖率、窗口伤害、死亡时间>
- 证据：<至少 3 个可比日志/本地事件摘要>
- 置信度：高 / 中 / 低
```

## 稳定性门槛

- 3/5 以上可比样本一致：可以作为“高手常用规律”。
- 2/5 一致且有明确阶段条件：写成条件规则，不要泛化。
- 只有 1 个样本：写“个人风格/待验证”。
- 不同版本、难度、英雄天赋混杂：拆成不同卡，不要合并。

## Boss 天赋总结

若用户要求“每个 Boss 的天赋字符串”，同时输出：

1. 可导入字符串或原始链接（若数据确实提供）。
2. 伤害节点、辅助节点、生存节点分别列出。
3. 该 Boss 为什么采用它：目标数量、阶段、转火、打断、驱散、位移或生存压力。
4. 使用边界：同一字符串在不同团队战术、难度或 M+ 怪包寿命下可能不再最优。

不要从截图或缺少节点信息的页面猜导入字符串；只能输出已验证的字符串，或明确说“无法可靠恢复”。

## 写入本地文件

默认只在回答中输出经验卡。用户明确要求沉淀时，才追加到指定 Markdown 文件，并保留：来源、版本、日期、置信度和待复核项。新证据与旧经验冲突时，不覆盖旧卡，新增“修订记录”并说明冲突原因。
