# 外部先例：jjholyfield/wcl-analyzer

参考项目：<https://github.com/jjholyfield/wcl-analyzer>。截至 2026-09-04 检查到的设计重点包括 WCL v2 GraphQL、事件分页、击杀/开荒模式、阶段分析、前五样本、死亡级联过滤和本地缓存。它是有价值的流程先例，但不是本技能的依赖。

## 借鉴的设计

- 将 WCL API 访问、令牌和分页集中在一个共享层，避免每个分析脚本重新实现。
- 事件查询持续处理 `nextPageTimestamp`，并缓存报告/战斗数据。
- 明确区分完整击杀与开荒夜：开荒看多场中位数、稳定性、阶段到达率和真正的前两次死亡。
- 先建立首领阶段/机制时间线，再计算每阶段 DPS 或技能执行。
- 通过多个高分样本提炼共同规律，而不是复制单个第一名。
- 死亡审计过滤团队级联死亡，避免把团灭后的死亡归罪给个人。

## 本技能的适配

- 支持中文用户和中国地区报告，不硬编码 US/EU；跨区比较时显式标注环境差异。
- 首先支持 WCL 在线链接和本地 JSON；没有 API 权限时可以降级为本地摘要，不要求用户配置秘密文件。
- 输出以中文对话、Markdown 经验卡和可执行训练计划为主，不要求生成 HTML 页面。
- 把“装备/构筑、任务分配、目标选择、触发链和技能次数”放在同一因果框架里，适用于任意职业，而不是只绑定某个团队流程。
- 保留可选的脚本化摘要，但不让脚本替代机制判断；所有自动结论都要回到原始事件核对。

## 不直接复制的部分

- 不复制其代码、固定路径、凭据存储方式或一次性团队页面。
- 不采用固定地区过滤、固定职业/首领规则或假设所有用户都有 Node.js 与 API 密钥。
- 不把“生成报告”误当成“完成复盘”：本技能的交付物是有证据的解释和下一把可验证动作。
